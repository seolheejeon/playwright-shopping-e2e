# Test Strategy – Playwright E2E Shopping Flow

## 1. 목적
본 문서는 B2C 서비스에서 핵심 사용자 흐름(로그인 → 상품 선택 → 장바구니 → 체크아웃)을 Playwright E2E 테스트로 검증하기 위한 전략을 정리합니다.  
또한 테스트 실패 시 증거(스크린샷/비디오/트레이스)를 자동으로 남겨 빠른 원인 파악과 재발 방지에 도움이 되도록 구성합니다.

본 문서는 특정 회사/서비스에 종속되지 않도록, QA 관점에서 **테스트 설계 → 실행 → 이슈 정리/우선순위 → 리포트/증거 수집**까지 운영 가능한 형태로 정리하는 것을 목표로 합니다.

---

## 2. 범위
### In Scope (포함)
- 로그인 성공 시나리오 검증
- 상품 선택 및 장바구니 담기 검증
- 장바구니 화면 진입 및 배지/리스트 반영 확인
- 체크아웃 진행(기본 정보 입력 후 완료 화면 확인)

### Out of Scope (제외)
- 실제 결제 연동(외부 결제/개인정보 입력이 필요한 시나리오)
- 성능/부하 테스트
- 보안 취약점 진단

---

## 3. 테스트 레벨 선택 이유 (E2E)
E2E 테스트는 사용자가 실제로 수행하는 핵심 플로우를 처음부터 끝까지 검증할 수 있어, 릴리즈 전 회귀(regression) 확인에 효과적입니다.

다만 E2E 테스트는 실행 시간이 길고 flaky(불안정)해질 수 있으므로 다음 원칙을 따릅니다.
- E2E는 핵심 플로우 중심으로 최소 개수만 운영합니다.
- 세부 기능/예외 케이스는 API/통합 테스트로 확장 가능한 구조로 설계합니다.

---

## 4. 우선순위 기준 (Risk-based)
테스트 우선순위는 사용자 영향도와 비즈니스 리스크를 기준으로 결정합니다.
- Priority High: 로그인/구매/결제 등 핵심 기능(매출·전환에 직접 영향)
- Priority Medium: 편의 기능(사용성 개선, 부가 기능)
- Priority Low: 문구/경미한 UI 등 기능 영향이 낮은 요소

본 프로젝트는 “구매 플로우” 검증을 목표로 하므로 High 우선순위로 분류합니다.

---

## 5. 안정성(Flaky) 방지 원칙
테스트 신뢰성을 높이기 위해 아래 원칙을 적용합니다.
- 임의의 sleep/wait 사용을 지양하고, UI 상태 기반으로 대기합니다.
- locator는 가능한 한 role 기반(getByRole) 또는 안정적인 selector를 우선 사용합니다.
- 테스트 계정/데이터는 fixtures로 분리하여 재사용성과 안정성을 확보합니다.
- 테스트는 독립적으로 실행되도록 설계하고, 상태 의존성을 최소화합니다.

---

## 6. 실패 증거 수집 (Evidence)
테스트 실패 시 원인 분석 시간을 줄이기 위해 아래 산출물을 자동 저장합니다.
- screenshot: only-on-failure
- video: retain-on-failure
- trace: retain-on-failure

산출물은 `test-results/` 및 `playwright-report/`에서 확인합니다.

---

## 7. 실행 및 리포트 확인 방법
### 로컬 실행
- `npx playwright test`

### HTML 리포트 확인
- `npx playwright show-report`

### 트레이스 확인
- `npx playwright show-trace test-results/**/trace.zip`

---

## 8. 향후 개선 계획
- 체크아웃 필수값 누락 등 예외 케이스를 추가하여 커버리지를 확장합니다.
- API 테스트(Postman 또는 Playwright request)를 추가하여 테스트 피라미드를 보완합니다.
- CI 환경에서 리포트 생성/배포를 안정화하여 팀 단위 품질 운영에 활용 가능하도록 개선합니다.
