# Test Coverage (Shopping Flow)

## 1. 목적
본 문서는 쇼핑 플로우(로그인 → 상품 탐색/선택 → 장바구니 → 체크아웃)의 기능을 기능 단위로 분해하고, 현재 자동화(E2E)로 커버한 범위와 향후 확장 계획을 정리합니다.

---

## 2. 기능 분해 (Feature Breakdown)
### A. 로그인
- 유효 계정 로그인
- 잘못된 계정/비밀번호
- 빈 값 입력
- 잠금 계정/에러 메시지(서비스 정책에 따라)

### B. 상품 목록/상품 선택
- 상품 목록 로딩
- 정렬/필터(존재 시)
- 상품 상세 진입(존재 시)
- 상품 장바구니 추가/제거

### C. 장바구니
- 장바구니 진입
- 담긴 상품 목록 표시
- 수량/배지 반영
- 상품 제거
- 체크아웃 진입

### D. 체크아웃
- 필수값 입력 및 검증
- 주소/결제 등 추가 단계(서비스에 따라)
- 완료 화면 확인
- 실패/예외 처리(필수값 누락, 네트워크 오류 등)

---

## 4. 커버리지 전략 (왜 E2E가 3개인가)
E2E는 사용자의 핵심 플로우를 빠르게 검증하는 데 효과적이지만, 실행 비용이 높고 flaky해질 수 있습니다.  
따라서 본 프로젝트는 **E2E는 핵심 플로우만 최소 유지**하고, 나머지 케이스는 아래 방식으로 확장하는 전략을 가집니다.

- 입력 검증/예외 케이스: API 또는 통합 테스트로 확대
- UI 문구/표현 차이: E2E보다는 컴포넌트/통합 또는 스냅샷 성격으로 분리
- 회귀가 중요한 핵심 플로우: E2E로 유지
