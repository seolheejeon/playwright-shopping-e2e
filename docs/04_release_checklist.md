# Release Checklist (Web/App 공통)

## 1. 목적
본 체크리스트는 기능 배포(릴리즈) 전후에 QA 관점에서 반드시 확인해야 하는 항목을 표준화하여,
회귀 결함을 줄이고 안정적으로 배포하기 위한 기준을 제공합니다.

---

## 2. Pre-Release (배포 전)

### A) 빌드/배포 준비
- [ ] 테스트 대상 브랜치/태그가 명확합니다.
- [ ] 변경 범위(기능/화면/API)가 릴리즈 노트에 정리되어 있습니다.
- [ ] 롤백(되돌리기) 방법이 공유되어 있습니다.

### B) 핵심 플로우 스모크 테스트
- [ ] 로그인/로그아웃이 정상 동작합니다.
- [ ] 핵심 사용자 플로우(예: 구매/예약/신청 등)가 End-to-End로 정상 완료됩니다.
- [ ] 주요 오류 케이스(필수값 누락 등)에서 안내 메시지가 정상 표시됩니다.

### C) 회귀 테스트(Regression)
- [ ] 이번 변경과 연관된 기능 영역의 회귀 테스트가 완료되었습니다.
- [ ] 기존 결함 재발 여부(재현/수정/재검증)가 확인되었습니다.
- [ ] 크로스 브라우저(최소 Chromium 기반)에서 주요 화면이 정상 동작합니다.

### D) 품질/운영 관점
- [ ] 사용자 영향도 높은 이슈(Severity High)가 0건입니다.
- [ ] 배포 차단 이슈(Blocking)가 0건입니다.
- [ ] 모니터링 지표/로그 확인 포인트가 정의되어 있습니다.

---

## 3. Release (배포 직후)

### A) 배포 결과 확인
- [ ] 배포 버전/커밋이 의도한 값과 일치합니다.
- [ ] 서비스 진입/핵심 화면 로딩이 정상입니다.
- [ ] 에러 페이지/권한 오류 등 치명 오류가 발생하지 않습니다.

### B) 간단 스모크 재확인
- [ ] 로그인 → 주요 기능 1회 수행까지 정상 확인했습니다.
- [ ] 주요 버튼/네비게이션이 동작합니다.
- [ ] 결제/주문 등 실제 트랜잭션이 있는 경우 샌드박스/테스트 환경으로 확인했습니다(가능 시).

---

## 4. Post-Release (배포 후 모니터링)

### A) 모니터링/알림 확인
- [ ] 에러 로그/알림(예: 5xx, Crash)이 급증하지 않습니다.
- [ ] 고객 문의/리뷰에서 신규 이슈가 증가하지 않습니다.
- [ ] 주요 지표(가입/구매/전환 등)가 급격히 하락하지 않습니다.

### B) 이슈 대응 프로세스
- [ ] 장애/이슈 발생 시 담당자/연락 채널이 명확합니다.
- [ ] 우선순위(Priority) 기준으로 트리아지하여 대응합니다.
- [ ] 필요 시 롤백/핫픽스 기준이 합의되어 있습니다.

---

## 5. 참고
- 본 체크리스트는 서비스 성격에 따라 항목을 추가/삭제하여 운영할 수 있습니다.
